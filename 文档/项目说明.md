## 关键机制与踩过的坑（改代码前必读）

1. **钩子回调必须极快**：回调里只做「识别按键 → `queue.put`」，其余（计数、写盘、刷新界面）都在 Tk 主线程的 `App.poll()` 里做，避免阻塞系统输入。
2. **不要周期性重装钩子**：曾尝试"每 60 秒卸载+重装做自愈"，实测重装窗口会丢点击（注入 12 次只记到 7 次），已回退成装一次不再动。
3. **`Shell_NotifyIconW` 在 `shell32.dll`，不在 `user32`**：写错会抛 `AttributeError: function 'Shell_NotifyIconW' not found`，且发生在子线程里会静默挂掉整个计数线程。
4. **托盘回调的参数格式（最坑的一个，务必按三种格式都兼容）**：
   回调消息里鼠标动作可能出现在三个位置，本机（Win11）实测是第 1 种：

   | 格式 | wParam | lParam |
   |---|---|---|
   | V1 / 本机实测 | 图标 ID (1) | 鼠标消息 `0x0201/0x0202/0x0204/0x0205` |
   | V2 / V3 | 鼠标消息 | 坐标 (x,y) |
   | V4（调用过 `NIM_SETVERSION`） | 低字=通知码 (`NIN_SELECT` 0x400、`WM_CONTEXTMENU` 0x7B) | 坐标 |

   只判断 `wParam` 会导致"代码看着没问题、单元测试也能过，用户真实点击毫无反应"。当前实现取
   `codes = (wParam & 0xFFFF, lParam & 0xFFFF)` 后与 `TRAY_LEFT_CODES` / `TRAY_RIGHT_CODES` 求交集。
   另外鼠标划过图标会持续送 `WM_MOUSEMOVE(0x0200)` 通知，所以**不要**把每条托盘消息都写日志。
5. **右键菜单必须在拥有该窗口的线程里调用**：在别的线程调 `TrackPopupMenu` 会立刻返回 0、菜单根本不显示（本机实测）。放在消息线程里调用不会卡死钩子——菜单自带模态循环会照常分发消息，实测菜单打开期间注入的点击依然全部计数成功。
6. **后台线程不能死，托盘窗口也不能丢（v2.4.2 补全）**：钩子回调、窗口过程、消息循环全部包了
   `try/except` 并写日志；`App.health_check()` 每 3 秒查一次「钩子线程存活」与「托盘窗口存活」：
   - 线程没了 → `start_worker(self.sink)` 整条重启；
   - **线程健在、只有托盘窗口没了 → 投递 `WM_TRAY_REBUILD`（`request_tray_rebuild()`），
     由钩子线程在自己的消息循环里 `ensure_tray_window()` 重建窗口并补挂图标。**
     这是以前的死角：`start_worker` 见线程还活着就直接 return，看门狗每 3 秒空转一次，
     图标再也回不来，只能重启程序。
   另外注册了 `TaskbarCreated` 消息，资源管理器重启后会自动重新添加图标。
   托盘窗口类现在**整进程只注册一次**（`_register_tray_window_class`），只留一个
   `WINFUNCTYPE` 引用（`_TRAY_WNDPROC`，成功注册后才存引用防 GC），回调运行时才从 `TRAY["sink"]` 取队列。

7. **打包后路径不能用 `__file__`**：`--onefile` 运行时 `__file__` 指向 `%TEMP%\_MEIxxxx`，会把数据写进临时目录并丢失。现在：`FROZEN = getattr(sys, "frozen", False)`，`APP_DIR = dirname(sys.executable)`。
8. **数据文件名**：`鼠标点击记录（配置文件，勿删）.json`（`DATA_NAME`）。
   首次读不到新名时会自动去旧名 `点击数据记录（勿删！！！）.json`、`data.json`
   （`LEGACY_DATA_NAMES`）里找并迁移，保存时统一写成新名。
9. **图标查找**：`find_icon_file()` 优先 `sys._MEIPASS\icon.ico`（v2.3.0 起 --add-data 内嵌），
   其次数据目录 → config → exe 同级 → 一级子目录；都没有则 `load_tray_icon()` 走 exe 内嵌资源兜底。
10. **单实例**：`MouseClickCounter_SingleInstance_v1` 互斥体；第二次启动 `SetEvent(MouseClickCounter_ShowWindow_v1)` 让已有实例弹窗后自己退出。
11. **.bat 必须纯 ASCII**：cmd 用 GBK 解析批处理，文件里写中文会乱码；exe 路径靠 `%~dp0` + `for %%F in ("%~dp0..\*.exe")` 动态取。
12. **强制结束进程会留下"幽灵托盘图标"**：点它没有任何反应（窗口早已不存在），容易被误判成"托盘功能坏了"。排查时先看进程是否还活着、`FindWindowW("MouseClickCounterTrayWindow", ...)` 是否返回句柄，再看 `tray.log`。正常退出（托盘菜单→退出程序）会 `NIM_DELETE` 清掉图标。
13. **exe 是 `--onefile`**：任务管理器里会看到两个同名进程（引导 + 主程序），属正常现象。
14. **测试/工具脚本必须隔离真实目录（血泪教训，已有 helper）**：`Stats()` 构造时
    `_load`→`_locate_existing` 会按真实搜索顺序找旧数据并 `_relocate` **搬走原文件**；
    `backup_dir()` / `auto_backup()` 读的是 `APP_DIR`，`log()` / `tray_log()` 读 `LOG_FILE` / `TRAY_LOG`。
    v2.0.0 开发期间测试脚本忘了打桩 `_data_search_dirs`，把用户真实数据迁移进临时目录后随
    `rmtree` 删除；幸而运行中的程序内存持有完整数据，注入一次点击促其落盘即恢复、零丢失。
    v2.4.2 起统一走 `测试/env.py`：
    - `env.isolate(mc)` —— 一次把 `EXE_DIR` / `APP_DIR` / `DATA_FILE` / `LOG_FILE` / `TRAY_LOG`
      **和** `_data_search_dirs` 全锁进临时目录。**只重定向 `DATA_FILE` 是不够的**
      （旧 `_pkg_tmp/render_shot.py` 就是这么写的，一跑就覆盖真实 `backups\`）；
    - `env.silence_backend(mc)` —— 把提权 `relaunch_elevated`、注册表 `set_startup`/`write_run_value`、
      计划任务 `create_logon_task`/`delete_logon_task` 换成**会直接抛错**的桩，
      测试一旦碰到真实系统就立刻红，而不是悄悄改了用户的自启动。
    若真发生误迁移且程序已退出：数据可能还在 `.tmp`/`.bad`/`.bak`、回收站，或备份目录 `backups\`。
15. **ctypes 有两类「只在打包版炸」的签名坑（v2.3.0 / v2.4.2 各一次）**：
    - **传参**：`LoadImageW` 未声明签名时，64 位模块句柄（`GetModuleHandleW` 返回值）被按 C int
      传递 → `OverflowError: int too long to convert`，异常在托盘线程内 → 看门狗每 3 秒重启一次、
      无限崩溃循环（源码运行走不到内嵌资源兜底分支，永远复现不了）。
    - **返回值**：`WINFUNCTYPE` 回调的 restype 是 `LRESULT`(`c_ssize_t`) 时，Python 侧 `return None`
      会被 ctypes 当成 -1 指针回转，抛 `ctypes.ArgumentError` **击穿原生栈**、把钩子线程一起带走。
      窗口过程兜底分支必须 `return int(ret) if ret is not None else 0`。
    凡新增 Win32 调用，先写 restype/argtypes 再用；`测试/test_ui.py` 里有扫描不变式
    （检查源码里每个 Win32 调用都声明了 restype/argtypes）当长期护栏。
16. **数据文件里一个坏值就能让程序「双击没反应」**：`"left": "abc"` 这类脏值以前在 `Stats()`
    构造期抛异常直穿 `main()`，打包版是 `--noconsole`，**没有弹窗、没有控制台、什么都不显示**，
    用户只会觉得 exe 坏了。现在：单值走 `_int_val` 坏值按 0；整份 JSON 结构异常时把原文件挪成
    `.bad` 后空启动（保留证据、不静默丢数据）。同类：缺键的旧行会让 `day_row`/`click_sum`/
    `sum_range_for` KeyError/TypeError，已全部改为 `.get(key, 0)`。
17. **跨线程 `DestroyWindow` 会失败**（`测试/probe_tray_win32.py` 实测撞出来的）：窗口只能由
    **创建它的线程**销毁。托盘窗口活在钩子线程里，所以界面线程绝不能直接 `DestroyWindow`——
    要拆就 `PostMessage(hwnd, WM_CLOSE, 0, 0)`，让 `DefWindowProcW` 在钩子线程的消息循环里拆。
    产品目前靠进程退出回收所以没踩到；看门狗将来若主动拆窗（而不只是重建）必须走这条路。
18. **备份目录里可能躺着「看起来完全正常」的合成数据**（2026-10-14 实测两例）：
    `文档\鼠标点击次数记录\backups\auto_2026-10-13.json` 与 `auto_2026-10-14.json` 曾被写入
    一份**每天严格等差递减 642、档案名「默认鼠标」**的演示数据（真实档案是两只 atk 鼠标，压根不在里面）。
    来源：① 未隔离的旧脚本在真实 `APP_DIR` 下跑过一次 `auto_backup`；② 修复时**拿错了参照物**
    （拿另一份同样被污染的备份当「真实快照」覆盖回去）。
    规矩：**修数据前先横向比对至少三份**（相邻日期的自动备份 + 部署前快照 + 实时文件），
    看逐日总量是否单调连续、档案 ID 与名称对不对得上；等差/等比数列、总量突然翻倍都是合成信号。
    现在恢复对话框的每一项都带 `_backup_label()` 摘要（文件名 · 点击总量 · 时间戳），
    选错至少能当场看见，不用等恢复完才发现。
19. **在 Tcl 回调里跑系统模态消息循环 = 让解释器重入，表现为闪退且日志一片空白**
    （v2.4.3 真实踩过，当天回炉）：无边框窗口拖动的「教科书做法」`ReleaseCapture()` +
    `SendMessageW(hwnd, WM_NCLBUTTONDOWN, HTCAPTION)` 在 Electron/Win32 里没问题，是因为
    它们的宿主循环本来就重入友好；Tkinter 不行——`DefWindowProc` 的模态循环会把 sent message
    再派发给 Tk 的窗口过程，而此刻 Tcl 正忙着执行 `<Button-1>` 绑定，**Tcl 解释器不可重入**，
    直接 `abort()`。现场特征：系统应用程序日志 `Application Error`，异常码 **0xc0000409**
    （UCRT failfast），出错模块 `ucrtbase.dll`；`error.log`/`tray.log` **一条都不会写**，
    因为 Python 层根本没机会抓到。副作用「先卡顿再闪退」也对得上：模态循环期间 `after` 全被
    阻塞，松手瞬间积压的定时器一次性引爆。
    规矩：**任何"把控制权交给外部消息循环"的调用都不能出现在 Tk 回调栈里**。
    要丝滑就另起线程用 `GetCursorPos` + `SetWindowPos`（`App._drag_loop`），
    线程里**只准用 Win32，一个 Tkinter 对象都不许碰**。
    代价说清楚：这么写就没有 Aero Snap 贴边和甩动最小化了，换来的是不崩。

## 数据格式（v2.2.0 起 version=3）

文件名 `鼠标点击记录（配置文件，勿删）.json`（`DATA_NAME`），旧名
`点击数据记录（勿删！！！）.json`、`data.json` 在 `LEGACY_DATA_NAMES` 里，启动自动迁移。

```json
{"app":"鼠标点击次数记录","version":3,"updated":"2026-10-06T21:00:00",
 "settings":{"autostart":true,"profile_id":"p1","disclaimer_ok":true,
   "profiles":[{"id":"p1","name":"默认鼠标","switch":"","added":"2026-10-04",
     "since":"2026-09-28","life":{"left":20000000,"wheel":10000000},
     "labels":{"x1":"前进键"},"hidden":["x2"]}]},
 "profile_days":{
   "p1":{"2026-10-04":{"left":8,"right":2,"middle":0,"x1":0,"x2":0,"wheel":0}}}}
```

键名：点击 5 键 `left/right/middle/x1/x2` + 滚轮 1 键 `wheel`（上/下滚合并计一格）。
滚轮从 v2.4.2 起**按格累积**：每条消息的 delta 累加到 `Stats.wheel_residual`，
每满 `WHEEL_NOTCH=120` 才 `+1`（高清滚轮 30/40 delta 不再每条只记 1）；
残量只在内存、不落盘，重启最多丢半格，所以**数据格式没变、仍是 `version=3`**。
`profile_days` 按档案 ID 分别保存每日计数，切换档案不再共用统计。
`version=2` 或更早的老文件只有一个顶层 `days`，`apply_payload` 会把它整体迁入
升级前的当前档案；其它档案从空数据开始。`version=1` 缺 `wheel`，或旧版分体
`wheel_up/wheel_down`，自动把上+下合并进 `wheel`；缺字段按 0 兼容。
写盘用「临时文件 + `os.replace`」原子替换，最多丢 3 秒数据。
`settings` 里存档案、显隐、重命名、备份位置、`last_auto_backup`、`autostart`、
`autostart_choice`（用户是否明确表过态）、`disclaimer_ok`（首次声明是否已确认）、
`theme`（auto/light/dark，v2.3.0 起）。

## 统计口径

| 列 | 算法 |
|---|---|
| 今日 | 当天各键累计 |
| 近7天日均 | 近 7 天累计 ÷ 7 |
| 总计 | 启动时累加全部历史 |
| 近一月热力 | 今天往前 28 天（向两侧补齐整周成 5×7）每天**点击合计**，`heat_color()` 映射颜色；非本月淡化 |

**点击口径/日均/热力日历用 `Stats.click_sum()`**（只累加 5 个点击键）；
滚轮 `wheel` 单独一行、不计入任何点击口径、不参与加权。
表格合计（数值）＝**表中可见点击键相加**（隐藏侧键不计入合计行，但 KPI 总点击含全部键）；
**合计行寿命＝加权**（用量 TOP1 权重 0.6、TOP2/3 各 0.2，仅含填了有效寿命的可见键，
`weighted_life_pct()`）；各寿命百分比**两位小数**、颜色 `life_color()` 渐变：
0-40 绿 / 40-70 绿渐黄 / 70-90 黄渐橙 / 90-100 橙渐红（锚点线性插值）。
首页寿命列与档案页百分比每 30 秒重算一次，不随每次点击刷新；点击计数仍按轮询更新。
亿级显示用 `fmt()`：≥1亿→"1.23 亿"，≥1000万→"3456.8 万"（数字不加千分位），其余千分位；
精确值用 `fmt_full()`，KPI 悬停切换。

## 统计窗口 UI（v2.0.0 起四页结构，v2.4.2 为现行形态）

顶部固定：**自绘标题栏**（`APP_TITLE` + `v{APP_VERSION}` + `BYLINE` + —/✕，底色 `CARD`，

`self._scroll` / `_sync_scrollregion` / `_on_wheel`），四个页面 `self.pages` 都 pack 在它里面，
切换用 `fill="x"`（不能用 expand，否则在 Canvas 里高度塌陷）。底部固定状态栏 `self.status`。

- **窗口大小恒定**：`_fit_window()` 首次按首页内容算出高度存入 `self._fixed_h` 后**冻结**——
  切页、增删档案都不再改变窗口尺寸；内容超出用滚动。位置首次居中+上 1/3，之后左上角锚定。
  `_chrome_h` 在 `show_page` 之前算好（`_build` 里已处理）。
- **首页**：日期行（含当前档案名）→ 3 个 KPI 卡片（`self.kpi`，悬停显精确值 `self.kpi_full`；
  标签行右侧环比箭头 `self.kpi_delta`：今日 vs 昨日、日均 vs 前 7 天，涨▲跌▼）→
  按键明细表（`self.table_row_widgets`/`self.cells`/`self.life_cells`/`self.life_dots`，滚轮行 + 合计行，
  隐藏键 `grid_remove`，寿命列两位小数 + `life_color` 渐变 + 同色圆点）→
  近一月热力日历（`self.canvas`，`draw_heat()`，悬停 `heat_hover()` 在 `self.week_note` 显示明细，
  下方图例 `self.heat_legend`）→
  按钮行（`self.btn_admin` 以管理员身份重启 / 隐藏到后台 / 退出程序）。v2.3.0 起警告黄框已移除。
- **设置页** `_build_settings`：按键显隐+重命名（`self.btn_rows`，左右中固定、侧键可隐藏）、
  界面模式三态、开机自启动勾选、备份位置/手动备份/从备份恢复、
  打开数据文件夹。复选框一律用自绘 `self._check`（选中＝实心 `ACCENT` 蓝方块 ■，未选＝空心 □），

  未勾选自启动时右侧挂 `⚠ 未开启，开机后不会自动记录`。**长路径 label 用 `wraplength` 换行、

- **从备份恢复** `restore_dialog` + `_backup_label`：下拉框显示的是摘要标签
  （`文件名　·　点击 N 次　·　时间戳`），确认时用 `labels.index(sel)` 映射回真实文件名。
  摘要读的是备份 JSON 本身，所以一旦备份内容与文件名不符（见踩坑 18），用户在按下
  「恢复」之前就能看见数字对不上。
- **档案页** `_build_profiles` + `render_profiles()`：每行一只鼠标，寿命进度、使用中高亮、

- **关于页** `_build_about`：版本、作者、GitHub 超链接（`_open_link`→webbrowser）、
  内嵌使用说明（`HELP_TEXT`）、免责声明。
- **悬停反馈（v2.4.2）**：`tk.Button` 原生只有按下色、没有悬停色，所以 `_btn()` 统一绑
  `<Enter>/<Leave>`（危险按钮用 `WARN_BG`，普通用 `BTN_HOVER`，离开回 `CARD`）；
  导航页签 `_nav_hover(name, enter)`（当前页不高亮）；明细表整行 `_row_hover(key, enter)`，
  行底色与高亮色记录在 `self._row_bg` / `self._row_hl`，合计行单独一档 `ROW_TOTAL_HOVER`
  （用 `BTN_HOVER` 会把合计行洗白）。**新增控件字典时必须同步 `__init__` 与 `switch_theme` 的重置清单。**

改界面时注意这几个钩子：

- **主题色/常量**：v2.3.0 起为双调色板 `App.THEME_LIGHT` / `App.THEME_DARK`（各 23 色，
  v2.4.2 新增 `ROW_TOTAL_HOVER`），`App._apply_palette()` 按 `theme_mode`（auto/light/dark）
  解析后把色值挂到 `self.BG/CARD/FG/…`，界面代码一律读 `self.XXX`，**不要再写死颜色**。
  字体统一用 `self.FONT`。
- **内置标题栏（v2.4.0，v2.4.2 定稿）**：系统标题栏隐藏，顶栏含程序名 + —/✕ 按钮（✕=隐藏到后台，同旧 X 行为），
  按住拖拽、双击最小化。实现是 `_strip_native_caption` 清 WS_CAPTION/WS_THICKFRAME + DWM 圆角，
  **绑定在 `<Map>` 上幂等执行**——Tk 每次映射都会加回 WS_CAPTION，构建时清一次无效；
  不用 overrideredirect（否则丢任务栏与最小化）。
  底色 v2.4.1 曾改成 `BG`（想去掉色差），实测整窗只有一层灰底时标题栏和正文粘成一片，
  v2.4.2 回到 `CARD`；**分隔线试过又被删掉**——用户要统一风格、少解释，色差够了。
- **标题栏拖拽＝独立线程搬窗口（v2.4.4）**：`_title_press` 取根句柄（`_root_hwnd` =
  `GetAncestor(winfo_id(), GA_ROOT)`）后起一个 `TitleDrag` 线程，`_drag_loop` 约 250Hz
  `GetAsyncKeyState(VK_LBUTTON)` + `GetCursorPos` + `SetWindowPos(SWP_NOSIZE|NOZORDER|NOACTIVATE)`。
  Tk 的 `<B1-Motion>` 只当兜底（拿不到句柄时才用 `_drag_off` 逐帧 `geometry`），两条路互斥：
  走线程就把 `_drag_off` 置 None。抬起靠 `GetAsyncKeyState` 自检，所以 `<ButtonRelease-1>`
  丢了也不会卡住；线程每次按下换一个 `threading.Event`，旧线程立刻收工。
  **别再试 `SendMessageW(WM_NCLBUTTONDOWN, HTCAPTION)`**：跟手确实好，但它会在 Tcl 回调栈里
  跑系统模态循环 → 解释器重入 → `abort()` 闪退（见踩坑 19，v2.4.3 就是发布出去后由用户实测撞出来的）。
  也**别退回 `<B1-Motion>` + `geometry()` 当主路径**：那是「事件采样 + Tcl 往返」，
  采样率封顶在 Tk 事件循环，窗口永远慢光标半拍。
  已知取舍：没有 Aero Snap 贴边与甩动最小化；拖动期间计数照常入队。
- **复选框自绘（v2.4.2）**：`App._check(parent, text, var, command, bg)` 返回一个 Frame，
  里面「实心蓝方块 / 空心灰方块」Label + 文字 Label，方块和文字都绑 `<Button-1>`，
  `var.trace_add("write")` 负责重绘（`command` 里回滚 var 也会正确还原）。
  为什么不用原生：`tk.Checkbutton` 画对钩、`ttk.Checkbutton` 画叉，同一页两种风格。
  **新增勾选类控件一律走 `_check`，不要再引入原生指示器。**
- **切换主题 = 整窗重建**：`switch_theme(mode)` 存 `settings.theme` → 销毁 root 全部子控件 →
  重置 `cells/life_cells/life_dots/table_row_widgets/kpi/kpi_short/kpi_delta/kpi_full/pages/nav`
  **和 `_row_bg/_row_hl`** → `_apply_style()` + `_build()` + `refresh(force=True, life_now=True)`；
  重建后**停在原页面**（v2.4.2 修复，原先被踢回首页）。新增控件字典记得同步重置清单。
- `self.kpi["today"/"avg7"/"total"]` 是三个大数字 Label，`self.kpi_delta[key]` 是环比 Label，
  `refresh()` 里 `configure(text=...)`；缩写/精确值分别存在 `self.kpi_short` / `self.kpi_full`，
  悬停切换由 `_kpi_hover()` 只改那一个 Label（**别在这里调 `refresh(force=True)`**，
  原先移出一次就重绘整页表格 + 35 格热力）。
- `self.cells[(按键, 列)]` 驱动明细表，列号 1=今日（整数）、2=近7天日均（一位小数）、3=总计（整数）。
  新增/删除列时同步改 `headers`、`chart` 和 `refresh()` 里的取整判断。
- 热力日历画在 `self.canvas` 上，逻辑在 `App.draw_heat()`：`<Configure>` 触发重画，数据来自
  `self.heat_grid`（35 个 date，5×7）与 `stats.days`；`heat_color(n)` = sqrt(n/8000)×100 喂 `life_color`，
  `HEAT_RED_CLICKS=8000` 为红点阈值；非本月格用 `mix_color(fill, HEAT_EMPTY, 0.82)` 淡化。
  三种空格要分清：**0 次 = 空心圆**、**有记录但当天没数据 = 小号「空」**、
  **还没到的日子（补齐整周时位于今天之后）= 「—」+ 悬停「还没到这一天」**（v2.4.2，
  之前统一画「空」会让人误读成「那天一次都没点」）。
  底部图例 `self.heat_legend` 五档取 200/2000/4000/6400/8000——`life_color` 锚点在 40% 以下
  （约 ≤1280 次）仍锁纯绿，档位取低了五档会重色、图例失去区分度。端点只写「少/多」，
  不加括号解释（用户要求简洁优先）。
- **状态栏（`self.status`，`update_status()` 每 2 秒刷一次）**：
  `v版本 · 运行中 · 权限 · 自启动方式 · 钩子告警`。
  非管理员时权限段直接写全「普通权限 ⚠ 未获取管理员权限，可能无法记录游戏内点击」并转
  `WARN` 色（只写「普通权限」三个字没人知道后果）；设置页自启动未勾选时
  `self.autostart_warn` 同步显示「⚠ 未开启，开机后不会自动记录」。
- 紧凑模式在 `_build()` 里按「逻辑高度」`winfo_screenheight() / DPI_SCALE < 900` 判定，
  压缩 `pad / self.row_h / KPI 字号`；`draw_heat()` 用 `self.heat_h` 算格高，两边必须一致。
- **所有像素量都要过 `App.px()`**（`px(v) = round(v × DPI_SCALE)`），字号用 point 单位；
  新增布局代码时别直接写裸像素，否则 125%/150% 下会和字号对不齐。
- 窗口尺寸：宽 560 固定、高按内容 `winfo_reqheight()` 算，位置 `max(20, (sh-h)//3)` 防止小屏跑到屏幕外。

## 构建命令

`version_info.txt` 在源码目录（exe 属性里的版本号、任务管理器显示名都来自它）。

**发版必改四处，且有机器校验**（漏一处就会出现「界面写 2.4.2、exe 属性写 2.4.1」）：

1. `mouse_counter.py` 的 `APP_VERSION`；
2. `version_info.txt` 的 `filevers` / `prodvers` / `FileVersion` / `ProductVersion`（共 4 个字符串）；
3. spec 文件名 / `--name`（`鼠标点击计数V<版本>.spec`，产出 exe 同名）；
4. `更新日志.md` 新增条目。

改完跑 `python 测试/check_version.py` 确认 `VERSION_OK`。

再加上 `--onefile --noconsole` 的托盘程序在后台**关不掉**（不用 taskkill 是硬约束）。
所以 `测试\check_frozen.py` 只核对打包产物的静态事实：归档含 `mouse_counter`/`icon.ico`/Tk、
没把数据文件塞进 exe、版本资源 = 当前 `APP_VERSION`、清单是 `asInvoker`（双击不弹 UAC）、PE 可加载、体积与上一版同量级。
**运行时行为（真钩子、托盘交互、`--dump`）必须由用户启动一次才算验证过**，别在报告里把它写成"已验证"。
清单里没有 `dpiAware` 声明是既有设计，DPI 感知由 `main()` 里 `tk.Tk()` 之前的
`enable_dpi_awareness()` 设置，v2.4.1 交付版一致。

## 已知限制 / 可继续做

- Windows 11 默认把新托盘图标收进「^ 隐藏的图标」，无法用程序强制常驻（只能手动拖出来）。
- 中键/侧键只有鼠标真的发出对应消息时才有计数；滚轮按"格"计（`WHEEL_NOTCH=120` delta 记 1，
  v2.4.2 起非 120 倍数的 delta 在内存里累积进位），横向滚轮未统计；
  多设备无法分别计数（低级钩子分不出消息来自哪只鼠标，需 Raw Input 另起架构）。
- DPI 按启动时主屏缩放适配，把窗口拖到缩放不同的另一块显示器不会立刻重排（重启即可）。
- 开机自启动写的是 exe 绝对路径，但 `sync_autostart` 每次启动会自愈到当前路径，挪位置无需手动重设。
- 右键菜单为三项：`控制面板`(IDM_SHOW=1001)、`切换鼠标档案`（二级菜单，命令 ID 从 `IDM_PROFILE_BASE=2000` 起）和 `退出程序`(IDM_EXIT=1003)；菜单定位在鼠标右上方。开机自启动入口在设置页复选框（v2.3.0 起 .bat 脚本已移除；`IDM_STARTUP` 常量与 sink 分支仍保留，需要时可加回菜单）。
- 待做（已讨论暂缓）：暂停记录、小时分布（需 version=4 先开始记小时桶）、CSV 导出、自定义时间段查询。
  （深色模式、热力日历已在 v2.3.0 完成；寿命告警用户明确不要。）

## 开机自启动（含排查手册）

实现：写 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，值名 `RUN_VALUE = "鼠标点击次数记录"`，
值为 exe 绝对路径（打包后就是 exe 本身，脚本运行时是 `pythonw.exe "mouse_counter.py"`）。
旧版本用过的值名 `MouseClickCounter` 会在设置/取消时一并删除（`RUN_VALUE_LEGACY`）。

**为什么值名要用中文**：任务管理器「启动应用」列表里显示的**就是 Run 的值名**（或 exe 的 FileDescription）。
原先叫 `MouseClickCounter`，用户在任务管理器里按中文名找，会以为"没有启动项"。
另外 exe 用 `--version-file version_info.txt` 打进了版本资源，`FileDescription=鼠标点击次数记录`，
资源管理器和任务管理器都会显示中文名、作者 `黎修源`。

**排查开机没起来的 4 步**：

1. `Get-ItemProperty "HKCU:\Software\Microsoft\Windows\CurrentVersion\Run"` → 看值名与路径是否存在、文件是否真的在那个位置。
2. `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\StartupApproved\Run`：
   首字节 `02` = 启用，`03` = 被禁用（用户在任务管理器里关掉过）；没有该项 = 默认启用。
3. 读系统日志 `Microsoft-Windows-Shell-Core/Operational`：事件 `9705/9706` = 开始/完成枚举 Run 键，
   `9707/9708` = 开始/完成执行某条命令（带 PID）。**这条日志能证明开机时到底跑了哪条命令**——
   本次故障就是靠它发现"开机执行的是 `mouse_counter.py` 而不是 exe"（旧的错误写法），所以看起来"自启动失效"。
4. 看程序自己的 `tray.log` 第一行：`程序启动 pid=... frozen=... cwd=...`（`main()` 里第一时间写），
   没有这行就说明进程根本没起来，不是程序内部问题。

**幽灵图标**：强杀进程会留下点不动的托盘图标，容易误判成"自启动失败"。正常路径退出（托盘→关闭程序）会 `NIM_DELETE` 清理。

### 静默启动（`--startup`）

自启动命令带 `--startup` 参数（`startup_command()` 里写死）。`main()` 里若检测到该参数，
在 `tk.Tk()` 之后、`App._build()` 之前就 `root.withdraw()`，窗口全程不映射 —— 开机只驻留托盘图标，
不弹窗、不抢焦点。单击托盘图标（或再次手动启动程序触发单实例唤醒）才会 `deiconify` 显示。

### 自启动自愈 + 偏好跟着文件夹走（迁移友好）

用户开/关自启动时，除了写注册表，还会把状态记进数据文件的 `settings.autostart`
（`Stats.set_setting`），所以**开关状态跟着文件夹一起被复制走**。`main()` 启动时调用
`sync_autostart(stats)` 做三件事：

1. 注册表里已有项、但命令与当前 exe 位置不一致 → 改写成当前路径（**换文件夹/换盘符自动修复**）；
2. 注册表里没有项、但数据文件记着用户开过 → 重新写入（**换电脑后手动打开一次即恢复**）；
3. 两处都没有 → 不动作，不擅自帮用户开启。

这就是主流软件的做法（应用每次启动自愈自己的开机启动项），比"只在开关时写一次"健壮得多。
副作用：同时存在多个副本时，**最后运行的那个副本会接管自启动指向**（测试副本也会抢占，测完记得把自启动指回正式目录）。

### 数据目录回退（只读位置不丢数据）

数据/日志的落点由 `_resolve_data_dir(EXE_DIR)` 决定，就是 `_data_search_dirs()`
里的第一个**可创建 + 可写**的目录（`makedirs` + 写 `.write_probe.tmp` 探测）：

1. `%USERPROFILE%\Documents\鼠标点击次数记录\` ← v1.3.2 起的正常位置
   （用 `SHGetKnownFolderPath(FOLDERID_Documents)` 取真实文档路径，OneDrive 重定向也对）；
2. `%USERPROFILE%\鼠标点击次数记录\`；
3. `<exe 同级>\config\`；
4. `<exe 同级>\`；
5. `%LOCALAPPDATA%\鼠标点击次数记录\config\`、`%LOCALAPPDATA%\鼠标点击次数记录\`。

数据文件、`error.log`、`tray.log` 都放这个目录。图标**不跟着走**，仍走
`find_icon_file()`：`sys._MEIPASS`（内嵌）→ 数据目录 → config → exe 同级 → 扫一级子目录。
窗口里的「打开数据文件夹」按钮（`App.open_folder()`）打开的是 `APP_DIR`，不是程序目录。

### 旧布局自动迁移（v1.3.1 / v1.3.2）

`Stats._locate_existing()`：若 `DATA_FILE` 不存在，就按 `_data_search_dirs()` 的顺序，
用 `DATA_NAME` 和 `LEGACY_DATA_NAMES`(`点击数据记录（勿删！！！）.json`、`data.json`) 逐个找老位置
（`config\` → exe 同级 → `其他文件\` → LOCALAPPDATA 各处 → 文档）；
找到后 `_relocate()` 把它搬进新位置（`os.replace`，跨盘符失败则 `shutil.copy2` + 删除），
并写一行 error.log；JSON 读失败会照旧备份成 `.bak`，结构正常但值坏掉的文件在 v2.4.2 起
先按 0 兜住、整份结构异常才挪成 `.bad`。
**改数据路径相关代码时务必保留这段兼容逻辑**，否则老用户升级后会出现「数据还在、界面全 0」。
测试：`测试/test_data.py` 覆盖「数据在旧文件名 / 跨目录迁移不丢字段 / 新位置优先 /
`.bak` 与 `.bad` / 坏值不炸整个文件 / v2 顶层 `days` 归入当前档案」等场景
（原 `测试\test_config_dir.py`、`test_log_rotate.py` 已删，覆盖面在此重建）。

### 高 DPI 适配（v1.3.2）

- `enable_dpi_awareness()` 必须在 `tk.Tk()` **之前**调用（`main()` 第一行）：
  `SetProcessDpiAwarenessContext(-4 /*PER_MONITOR_AWARE_V2*/)` → 失败退
  `shcore.SetProcessDpiAwareness(2)` → 再退 `SetProcessDPIAware()`；
  然后用 `GetDeviceCaps(LOGPIXELSX)` 算出 `DPI_SCALE = dpi/96`（96=1.0，120=1.25，144=1.5）。
- 界面所有像素量（窗口宽、外边距、表格内边距、热力格高、标题栏行高等）都经 `App.px()` 缩放，
  字号用 point 单位并显式设 `tk scaling = 1.3333 × DPI_SCALE`，保证「字」和「间距」同比放大。
- 小屏判断用逻辑高度：`winfo_screenheight() / DPI_SCALE < 900` 才进紧凑模式。
- 验证：`测试\render_preview.py`（会调用 `enable_dpi_awareness()`，本机 125% 下截图尺寸应与窗口一致），
  实机截图用 PrintWindow + GetDIBits（render_preview.py 已封装；注意：进程不声明 DPI 感知时
  `GetWindowRect` 返回的是虚拟化坐标，截图会错位/被放大）。

### 管理员权限与「游戏内点击统计不到」（v1.2.0）

**现象**：带内核反作弊的游戏（实测《明日方舟：终末地》，目录内含
`AntiCheatExpert\ACE-BASE.sys`、`ACE-CORE*.sys`、`ACE-Service64.exe`，服务名
`AntiCheatExpert Protection`）在游戏内点击完全统计不到。

**结论**：这是 **Windows UIPI（用户界面特权隔离）** 导致的——游戏以高权限运行，
普通权限进程安装的低级鼠标钩子收不到发往高权限窗口的输入（与 AutoHotkey
「脚本在管理员窗口里不生效」同源）。实测以管理员身份运行本程序后，游戏内点击正常统计。

**排除项**：不是「游戏用原始输入（Raw Input）」的问题——用 `RIDEV_NOLEGACY`
（游戏常用的原始输入模式，原验证脚本 `work\rawinput_nolegacy_test.py` 已丢失、未重建）
实测，钩子照样收到并统计点击。
也不是"反作弊把钩子摘掉"这种可以自愈的情况（这种情况本程序的自诊断会记录下来）。

**实现**：
- `is_elevated()` 用 `shell32.IsUserAnAdmin()` 判断；
- 手动启动（非 `--startup`、非 `--elevated`）时，若没有管理员权限 →
  `relaunch_elevated()` 通过 `ShellExecuteW("runas", ...)` 提权重启（带 `--elevated` 标记防止递归；
  用户取消 UAC 时重新抢占互斥体、继续以普通权限运行）；
- 开机自启优先用**计划任务**（`create_logon_task()`）：
  `schtasks /create /tn 鼠标点击次数记录 /xml <临时XML> /f`（**不要用 `/tr`**，见下）。
  计划任务以最高权限运行**不会弹 UAC**，且钩子处于高完整性级别；
  没有管理员权限时 `schtasks` 会失败（实测返回 False），自动回退写注册表 Run；

  **踩坑：`schtasks /tr` 的引号解析**。写成
  `schtasks /create /tr "\"C:\路径\app.exe\" --startup" /sc onlogon /rl highest`
  时，schtasks 会把带引号的路径+参数拆错（实测把 `"…\app.exe" --startup` 变成
  `…\app.exe\ --startup`），报**"参数错误"**而不是权限错误，所以即使有管理员权限也建不成功。
  现在改成生成任务 XML（`task_xml()`）再 `schtasks /create /xml`，Command/Arguments/
  WorkingDirectory 写在 `Exec` 节点，顺带设置了 `RunLevel=HighestAvailable`、
  登录触发器、`ExecutionTimeLimit=PT0S`、`DisallowStartIfOnBatteries=false`。
  非管理员执行时错误信息是"拒绝访问"，说明 XML 本身是对的。
- `task_command()` 读 `schtasks /query /tn ... /xml ONE` 解析任务的 Command/Arguments，
  用于路径自愈（exe 换位置后重建任务）；
- 自诊断 `check_hook_blocked()`：`system_idle_seconds()`（`GetLastInputInfo` + `GetTickCount`）
  与 `HOOK_STATE["last_event"]`（钩子回调时间）对比，异常时写 tray.log 并
  `request_hook_reinstall()`（PostThreadMessage 到钩子线程重装钩子）。

**测试注意**：带 `--elevated` 启动可以跳过提权（自动化测试用这个，否则会弹 UAC）。
