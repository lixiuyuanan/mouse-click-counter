## 1. 项目一句话

Windows 鼠标点击/滚轮计数工具：低级钩子（WH_MOUSE_LL）统计五键点击 + 滚轮格数，
tkinter 界面 + 托盘常驻，鼠标档案与微动寿命预测，近一月热力日历，深浅色主题，
每日数据落 JSON，支持备份恢复。**纯自用定位**：无云服务、无代码签名、无第三方运行时依赖
（PyInstaller 仅构建期）。交付形态 = 单 exe（v2.3.0 起图标与使用说明均内嵌）。

- **v2.4.3**（10-14 下午，已部署后被用户实测**否掉**）：只改一件事——**拖窗口时窗口跟手**。
  按下标题栏改为 `ReleaseCapture()` + `SendMessageW(hwnd, WM_NCLBUTTONDOWN, HTCAPTION, 0)`，
  让 `DefWindowProc` 的模态循环驱动移动。用户实测结论：**「UI 可以正常跟随了，但是拖动后会卡顿，然后闪退」**。
  病因：在 Tk 的 `<Button-1>` 回调里跑系统模态循环＝在 Tcl 解释器忙的时候把 sent message 重入派发给 Tk，
  Tcl 不可重入 → `abort()`，WER 记 `0xc0000409` / `ucrtbase.dll`，Python 侧 `error.log` 一声不响；
  卡顿则是模态循环期间 Tk `after` 被堵、松手后集中补火。用例 79→82 项。
  **教训：82 项全绿挡不住原生层崩溃**——`_FakeCaption` 桩只记调用，不会真的重入 Tcl。

- **v2.4.4**（10-14 晚打包，10-16 由用户启动并投入使用）：拖拽改回**自己实现的独立线程**：
  `_title_press` 取根句柄后起一个 daemon 线程 `_drag_loop`，约 250 Hz 采样
  `GetAsyncKeyState(VK_LBUTTON)` + `GetCursorPos` → `SetWindowPos`，**循环里绝不碰任何 Tk 对象**；
  松手由 `GetAsyncKeyState` 自己判，抬起事件丢了也不会卡住。双击最小化仍走手动比对
  `event.time` 与 `GetDoubleClickTime()`。拿不到根句柄时退回原来的 Tk `<B1-Motion>` 兜底路径。
  代价：**放弃 Aero Snap 贴边与甩动最小化**（交给系统才有，换稳定性）。
  用例 82→84 项（`test_ui.py` 46→48：系统拖拽那三条改写成线程版 + 新增「抬起丢失/窗口销毁线程自己收工」)；
  无视觉变化所以没重出预览图。详见 文档/项目说明.md 踩坑 19。

## 5. 构建与发布流程（v2.4.4 版）

```powershell
# 0) git status 确认干净；把源码+数据压一份进 备份\（发版前必做）
# 1) 语法 + 回归 + 探针 + 版本闸门（全部不碰真实数据/真实系统）
python -m py_compile mouse_counter.py
python 测试\run_tests.py            # 应输出「通过 84，失败 0」
python 测试\probe_tray_win32.py     # 应输出 TRAY PROBE PASS
python 测试\check_version.py        # 应输出 VERSION_OK（spec 在 构建\，其次才回退找 _pkg_tmp\）
# 2) 界面目检（隔离数据，输出 预览图\v{APP_VERSION}_*.png）
python 测试\render_preview.py
# 3) 打包（--add-data/--icon 必须绝对路径，相对路径按 spec 目录解析会找不到文件）
python -m PyInstaller --noconfirm --clean --onefile --noconsole --name "鼠标点击计数V2.4.4" `
  --add-data "D:\PYCH\AI agent\鼠标点击次数记录\icon.ico;." `
  --icon "D:\PYCH\AI agent\鼠标点击次数记录\icon.ico" `
  --version-file version_info.txt `
  --distpath _pkg_tmp\dist --workpath _pkg_tmp\build --specpath 构建 mouse_counter.py
# 3b) 打包产物静态核对（不启动 exe！）—— 应输出 FROZEN_CHECK_PASS
python 测试\check_frozen.py
# 4) 部署（⚠️ 需用户明确同意：要结束进程、覆盖交付 exe、动计划任务）：
#    用户从托盘「退出程序」→ 旧 exe 移入 备份\旧版exe\ → 新 exe 拷进交付目录 →
#    **由用户亲手双击并接受 UAC**（只有提权实例能让 sync_autostart 把计划任务指到新路径）
# 5) 验证：tray.log 出现「程序启动 … / 鼠标钩子安装成功 / NIM_ADD 成功」，
#    且数据 json mtime 前进；--dump 输出重定向到文件按 UTF-8 读
```

发版必改四处：`APP_VERSION`、`version_info.txt` 四处版本号、spec/`--name` 的 exe 名、`更新日志.md` 新条目
——`测试/check_version.py` 会校验前三处。exe 文件名带版本号，换版本时交付目录旧 exe 移入 `备份\旧版exe\`。
**v2.4.2（10-14 16:00）、v2.4.3（10-14 16:30 前后）都已部署过**，v2.4.3 被用户实测否掉（拖动后闪退），
v2.4.4 于 10-14 16:52 打包、10-16 由用户启动至今，交付目录只剩 `鼠标点击计数V2.4.4.exe`。
**agent 不要代拉 exe**：用 `open` 起的是非提权实例，UAC 被拒后它会照常跑，给出「部署成功」的假信号，
而计划任务仍指向旧路径（2026-10-14 踩过）。开发阶段之所以不启动 exe，是因为它一起来 `APP_DIR` 就落到真实的
「文档\鼠标点击次数记录」，开发机拦不住它写，而且托盘程序不用 `taskkill` 关不掉。

  抬起丢失或窗口销毁时线程自己收工／双击最小化不重复起线程／拿不到根句柄退回 Tk 移动，
  均用 `_FakeCaption` 桩替换 `_caption_api` + `_no_thread`  recorder 替换 `threading.Thread`，
  不真起线程）、ctypes 签名扫描不变式…）+
  `测试/probe_tray_win32.py`（真注册类/真建窗/真发托盘消息/类只注册一次/WNDPROC 不增长/
  创建线程 WM_CLOSE 拆窗）+ `测试/check_frozen.py`（打包产物静态核对）+ `--dump` + tray.log。
- **仍缺**：钩子端到端（`WH_MOUSE_LL` 真装钩子 + `mouse_event` 注入）没有自动化，
  只有手工注入脚本；`_worker_main` 的消息循环、`TrackPopupMenu` 模态循环靠实机实测；
  **frozen 运行至今没有自动化能覆盖的手段**——`check_frozen.py` 只核对产物完整性
  （归档内容/版本资源/清单/体积），exe 本身一次都没跑过，因为它一起来就写真实数据目录，
  而且后台托盘程序不用 `taskkill` 就关不掉。这一条只能等用户启动新版时补齐。
- **桩挡不住原生层崩溃**：v2.4.3 的闪退是在 82 项全绿的状态下发出去的。`_FakeCaption` 只记录调用，
  不会真的把 sent message 重入派发给 Tcl，所以「Tcl 不可重入」这类**只能在真 Win32 环境复现**的 bug
  必须在交付目录上真人跑一次才算过。改拖拽/钩子/模态循环相关代码时，别把单测全绿当验收。

- **血泪教训**：任何测试/工具脚本必须 `env.isolate(mc)`（含 `APP_DIR`，不只 `DATA_FILE`）
  + `env.silence_backend(mc)`；绝不在真实数据目录跑写操作。详见项目说明踩坑 14。
- **打包版陷阱**：Win32 调用不声明 argtypes/restype、或窗口过程 `return None` 的 bug
  只在 frozen 环境触发（源码运行走不到兜底分支），改 ctypes 相关代码本应打包实测；
  不能实测时至少跑 `probe_tray_win32.py`（真 Win32 调用）+ `check_frozen.py`，
  并人工核对每个新加的 Win32 调用都声明了 `argtypes`/`restype`（`test_ui.py` 有一条扫描不变式）。
  见项目说明踩坑 15/17。

## 9. 已知限制（如实）

- 非管理员时游戏内（DirectInput 独占 / UIPI）点击不计数（状态栏有权限提示，可用「以管理员身份重启」）。
- **滚轮已在 v2.4.2 修好**：按 120 delta 一格累积进位，高清滚轮不再系统性少计；
  残量不落盘（重启最多丢半格）。横向滚轮仍未统计；多设备无法分别计数（需 Raw Input 另起架构）。
- 托盘右键菜单为系统原生绘制，不随深色模式变色。
- 未做代码签名，SmartScreen 首次运行会提示。
- 数据只增不清理；小时分布需 version=4 先记小时桶（暂缓）。
- **换版本会让计划任务路径过期**（本次部署实测清楚）：任务里存的是**带版本号的绝对路径**，
  换版本必然对不上。`sync_autostart` 能自愈，但**前提是用户手动启动过一次新版并同意 UAC**；
  若只删旧 exe 拷新 exe 而从没手动跑过，下次开机任务静默失败（Last Result 0x2，无任何提示），
  程序从此不记录。若 UAC 被拒，任务留在旧路径、而 `startup_enabled()` 只看 `task_exists()`，
  界面仍显示「开机自启动」已勾选——**误导态，尚未修**（修法见下条建议）。
- **建议的三处小修**（未落码）：① 任务过期且重建失败时退到注册表 Run，而不是顺手 `delete_run_values()`
  把唯一能在普通权限下生效的路也清掉；② 勾选状态改为校验任务指向的文件存在且等于当前 exe，
  否则显示 ⚠ 并给一键修复；③ 撞车退出时提示「已有一个实例在运行（版本 X）」，
  免得用户以为启动的是新版。
